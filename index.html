1这是什么？——一句话：一台"自动获客的发动机"

给非技术朋友的一句话解释：别人在抖音/小红书发内容等客户来，这台系统反过来——自动去俄罗斯的社交平台找"正在找物流的人"，筛选出最值得聊的，然后帮你打招呼、跟进。

🎯 给谁用

广东阿尔泰国际物流（中俄物流专线）。目标是：找到俄罗斯市场"需要从中国发货"的客户——进口车商、电商卖家、批发商、个人代购。

🌍 在哪些平台

VK（俄罗斯微信）、Telegram、Instagram、TikTok、WhatsApp、速卖通——覆盖俄罗斯主流社交 + 电商平台。

⚙️ 做什么

采集线索 → AI 评分 → 客户画像 → 话术触达 → 自动跟进 → 每日报告。一条完整获客流水线。

🏠 跑在哪

一个 Docker 容器，装在客户的电脑/服务器上。完全独立，不依赖任何第三方，7×24 自动运行。

💡 小白解读
你可以把它想成一台"钓鱼机"：它自己撒网（采集）、自己看哪条鱼值得钓（评分）、自己准备鱼饵（画像+话术）、自己甩竿（触达）、自己盯着有没有鱼上钩（跟进）。老板和员工只需要打开网页看结果、点几下按钮。

为什么是"容器"而不是普通软件？

对比普通软件（装个 App）容器（我们做的）
安装每台电脑环境不同，很容易装不上环境 100% 一致，一条命令启动
运行依赖桌面程序开着完全独立，电脑开机自己跑
升级重新下载安装包，可能丢数据换一个新镜像，数据卷保留
换机器重新配置一遍拷贝镜像 + 数据，秒级迁移
多平台Mac/Win 各做一套同一套代码，Mac/Win/Linux/云服务器都跑

# 看日志（出问题排查用）

# 升级到新版本

git pull                    # 拉新代码
docker compose up -d --build  # 重新构建并启动

# 数据备份（自动 + 手动）
# 自动：每天 09:00 / 14:00 / 21:00 自动备份到百度网盘
# 手动：

5设计理念——为什么这么设计

这套系统不是"把功能堆起来"，每个关键设计都有明确理由。给客户讲"我们为什么这么做"时用这一章。

🎯 五个核心设计原则

🛡️ 1. 安全第一：fail-closed

发送功能默认 disabled。配置错误 = 不发送（绝不乱发）。要真正发消息，必须逐项确认（send_mode 从 disabled → dry_run → approval → live）。

防"系统自己乱发骚扰客户"

🎯 2. 规则说了算

每条消息都有筛选条件 + 对话理由（R0-R4 规则链），可追溯、可审计、可防投诉。

不是 AI 乱聊，是规则驱动

🤖 3. 评分排序 + 配额分配

平台私信额度稀缺（VK 约 10 条/天）→ 不是看到谁发谁，而是 5 维评分排序，把每一天的额度花在最值的人身上。

筛得越准每一发越值钱

👤 4. 员工可追溯

每个员工登记名字 → 每次操作审计（谁/什么时间/IP/干了什么）→ 老板随时能查"谁在联系谁"。

不是监视，是保护业务资产

🧩 5. 容器化独立

不依赖 Hermes、不依赖任何第三方服务。一套代码 Mac/Win/云都能跑。升级只换镜像，数据卷保留。

交付简单、运维省心

6交付 SOP——从零到开箱即用

给客户的交付流程。核心原则：客户不需要懂 Docker、不需要懂技术，他要的是"打开就能用"。

📦 交付物 = 一个"交付包"

1️⃣ 镜像文件 / 构建脚本

altai-docker 镜像（可离线导入）或构建脚本（在线 docker build）。

2️⃣ compose + 配置

docker-compose.yml：端口/数据卷/环境变量/健康检查全配好。

3️⃣ 数据目录

config/（话术/关键词/黑白名单）+ data/（空业务库）。开箱即用。

4️⃣ 一键启动脚本

Mac 双击 启动.command，Windows 双击 启动.bat。

5️⃣ 交付文档

本说明书（网页版）+ 员工操作指南 + 交付与运维全攻略。

6️⃣ 自检工具

healthcheck + watchdog（8 项巡检）+ 自检页面。系统健康随时可见。

🚀 交付 7 步（小白可执行）

  1. 安装 Docker（远程帮忙装，或交付包内置引导）。Mac 装 Docker Desktop，Windows 装 Docker Desktop/WSL2。
  2. 解压交付包到任意目录（建议桌面，路径别带中文/空格）。
  3. 双击启动脚本。自动：检查 Docker → 导入/拉取镜像 → docker compose up -d → 自动打开浏览器。
  4. 看到运营看板 = 交付成功。绿色健康检查、引擎待启动、规则已就位。
  5. 员工登记：点右上角 👤 输入名字（员工追溯开始）。
  6. 平台登录：在浏览器登录 VK/WA/TG/IG/TikTok/速卖通（一次性，登录态保存）。
  7. 开始获客：点「▶ 开始获客」。扫描线动起来 = 系统在工作。
⚠️ 交付前必查
① 网络：海外平台需要科学上网（代理）——先确认客户网络环境。
② 账号：6 个平台的业务账号要提前准备好（VK 主账号要有 messages 权限）。
③ 备份：交付完成后立即做一次全量备份到客户百度网盘。
④ 演练：交付前先在测试机完整走一遍 7 步，找优化点（远程演练经验）。

7使用 SOP——员工每天怎么用

员工每天上班只需要 3 步，全程不超过 2 分钟。其余系统自动跑。

📌 每天上班 3 步

  1. 打开系统：浏览器输入 http://127.0.0.1:8890/，回车。
  2. 确认是你：右上角显示 👤 你的名字 → 跳过；显示"未识别"→ 点它输入名字。
  3. 看今日任务：点「📌 今日任务」里的数字（🔥 高意向待聊 / 📋 未联系客户 / 🆕 今日新增 / ⏰ 今日跟进），系统告诉你今天该聊谁。

💬 今天该聊谁？——线索工作台

  1. 点「🔥 优先跟进」：看到 A/B 级未联系客户（最值得聊的）。
  2. 点「📇 档案」：看客户的 360° 档案——他是谁、做什么生意、AI 分析他可能需要什么、怎么开口。
  3. 点「💬 直接聊」：复制 VK/TG 链接去平台开聊（或系统帮你发）。
  4. 聊完点「📞 联系」：标记"已聊过"，系统自动排 D+1/D+3 跟进计划。
💡 小白解读
员工不需要懂采集、评分、画像这些技术名词。系统把"几万条帖子"变成了"今天该聊的 5 个人"，员工只需要：看档案 → 开聊 → 标记。这就是"获客引擎"和"人工大海捞针"的区别。

📈 怎么看"获客有没有效果"

采集 2199 → 评分 1074 (48.8%) → 高意向 179 → 触达 11 (6.1%) → 回复 0
⚠️ 当前核心问题
采集和评分没问题，断点在"触达"（6.1%）和"回复"（0%）。意思：找到的人不少，但真正去聊的人太少、聊了没人回。这不是系统坏了，是触达动作没真正跑起来（见第 11 章完善方向）。

9安全红线——fail-closed 与风控

这套系统最重视的就是"安全"——不骚扰客户、不封号、不乱发、不泄露。下面是所有安全机制。

🛡️ 发送闸门（最核心）

模式含义能发消息吗
disabled（默认）完全关闭❌ 只能看、不能发
dry_run演练❌ 只打印"会发给谁"，不真发
approval_only人工审批✅ 每条要老板确认
test_allowlist白名单✅ 只发给自己测试号
live_supervised真实发送✅ 真实触达（有监督）
🚨 铁律
默认 disabled。配置缺失/格式错误 = 按 disabled 处理（fail-closed）。只有明确改配置并确认，系统才可能真正发消息。这是防"系统乱发骚扰客户导致封号"的第一道防线。

🔐 访问安全

🔑 开发者模式门禁

每次进开发者模式要重新输密码；输错 5 次锁 10 分钟；密码不落盘明文。

👤 员工识别

每个操作绑定员工名 + IP，审计可追溯"谁干的"。

🛡️ CSRF 防护

所有写操作校验来源（Origin 非本机 403）。

📝 全量审计

引擎/账号/线索/开发者模式所有操作都有时间+操作者+详情。

🖥️ 平台风控（防封号）

🚫 个性化文案

每条消息引用对方帖子，绝不群发相同内容。

⏱️ 限速

VK 间隔 90-150 秒、日限 10 条、跨平台 20 条/天。

🚦 1+1+1 策略

首触达 → D+3 跟进 → D+7 告别，不骚扰。

🛑 熔断

单日举报 >2 次 → 立即全停；VK 警告 → 停 7 天。

12客户百问百答——客户可能会问的 20 个问题

这些是客户（老板/员工）最可能问的问题，点击展开看答案。拿去就能用。

这系统是干什么的？一句话说清楚

它是一台"自动获客的发动机"：自动去俄罗斯的 VK/Telegram 等平台找"正在找物流的人"，用 AI 筛出最值得聊的，生成客户画像和话术，帮你触达、跟进。

我要不要懂技术？要装什么？

完全不用懂技术。交付包双击启动，浏览器打开网页就能用。唯一的环境要求是装一个 Docker（我们远程帮你装好）。

它和微信/抖音那些工具一样吗？

不一样。那些工具是"发内容等客户来"，这套是"主动去找客户"——去俄罗斯社交平台找正在找物流的人，AI 筛选后主动触达。

为什么用容器而不是装个软件？

容器 = 环境 100% 一致 + 完全独立运行 + 升级不丢数据 + 换电脑秒级迁移。对客户来说就是"打开就能用，不用折腾环境"。

它真的能自己抓数据吗？

能。目前已经真实采集了 VK 2199 条、Telegram 495 条等线索，都是真实平台数据。采集、评分、画像、话术都是真实跑通的。触达需要平台登录后激活（一次性配置）。

会不会乱发消息骚扰客户？

不会。系统默认"只读不发送"（fail-closed），要真正发消息必须老板确认。而且每条消息都个性化引用对方帖子，绝无群发，还做了限速（每天最多 10-20 条）、防封号设计。

会不会被封号？

做了完整防封设计：个性化文案、随机间隔、日限额、1+1+1 跟进策略（不骚扰）、单日举报超 2 次自动全停。但任何自动化都有风险，所以默认谨慎。

数据安全吗？会不会泄露？

数据在你自己电脑/服务器上，不经过我们。每天 3 次自动备份到你自己的百度网盘。员工操作全部审计可追溯。

员工不会用怎么办？

每天 3 步：打开网页 → 确认名字 → 看今日任务。系统已经告诉你今天该聊谁、怎么聊（档案里有 AI 建议话术）。全程 2 分钟。本说明书第 7 章有完整图解。

老板怎么看效果？

打开看板看 4 个地方：引擎状态（绿=正常）、业务漏斗（采集→评分→高意向→触达→回复）、今日任务（今天该聊谁）、目标 vs 实际（进度条）。

电脑关机了系统还跑吗？

容器设了"开机自启"：电脑一开机它就自己跑。但电脑关机时它不跑（它跑在电脑上）。要 7×24 不关机，建议放一台常开的电脑或云服务器。

手机能打开看板吗？

同一网络下手机浏览器输入 http://电脑IP:8890/ 可以打开（需防火墙放行）。要任何地方都能访问，需要部署到云端（可选服务）。

升级会不会丢数据？

不会。数据存在独立数据卷，升级只换程序镜像。而且升级前有版本保存 + 云备份双保险，出问题一键回滚。

出问题了找谁？

系统有 8 项自动巡检（watchdog），出问题自动推微信告警。还有本说明书第 10 章故障排查表。解决不了找我们远程支持。

VK 是什么？为什么主做 VK？

VK 是俄罗斯最大的社交平台（相当于俄版微信+Facebook）。做中俄物流，VK 上的进口车商、电商卖家、批发商最活跃，B2B 客户浓度最高，所以是主战场。

系统怎么判断"这个客户值得聊"？

5 维 AI 评分：意向度（是不是在找物流）、匹配度（是不是做中国进口）、账号质量（活人/商家）、画像完整度、触达价值。80 分以上 S 级，70 以上 A 级。系统只让你聊 A 级以上。

客户回复了怎么办？

VK 每 2 分钟巡查回复，检测到回复 → 立即停止自动发送 → 转人工处理（标记 needs_human，通知你）。问价的客户绝不让 AI 乱答。

能同时多个员工用吗？

能。每个员工登记自己名字，系统区分谁在联系谁（员工追溯）。可以创建多个客资账号，各管各的客户。

这套系统要多少钱？

交付按企业级标准：完整交付包（容器应用 + 多账号 + 总机监控 + 检测 Agent + 版本回滚 + 全套 SOP 文档）+ 现场激活 + 远程运维支持。具体报价联系交付方。

我们想扩展新平台怎么办？

架构是插件化的：新平台加一个采集器 + 适配器即可。TikTok/速卖通已经就绪，随时可扩展（如 Ozon、Wildberries 等俄本土电商）。
