1这是什么？——一句话：一台"自动获客的发动机"

给非技术朋友的一句话解释：别人在抖音/小红书发内容等客户来，这台系统反过来——自动去俄罗斯的社交平台找"正在找物流的人"，筛选出最值得聊的，然后帮你打招呼、跟进。

🎯 给谁用

广东阿尔泰国际物流（中俄物流专线）。目标是：找到俄罗斯市场"需要从中国发货"的客户——进口车商、电商卖家、批发商、个人代购。

🌍 在哪些平台

VK（俄罗斯微信）、Telegram、Instagram、TikTok、WhatsApp、速卖通——覆盖俄罗斯主流社交 + 电商平台。

⚙️ 做什么

采集线索 → AI 评分 → 客户画像 → 话术触达 → 自动跟进 → 每日报告。一条完整获客流水线。

🏠 跑在哪

一个 Docker 容器，装在客户的电脑/服务器上。完全独立，不依赖任何第三方，7×24 自动运行。

💡 小白解读
你可以把它想成一台"钓鱼机"：它自己撒网（采集）、自己看哪条鱼值得钓（评分）、自己准备鱼饵（画像+话术）、自己甩竿（触达）、自己盯着有没有鱼上钩（跟进）。老板和员工只需要打开网页看结果、点几下按钮。

为什么是"容器"而不是普通软件？

对比普通软件（装个 App）容器（我们做的）
安装每台电脑环境不同，很容易装不上环境 100% 一致，一条命令启动

🟦什么是 Docker？——为什么这套系统要装在"容器"里

给完全不懂技术的人看。看完这一章，你就明白"容器"是什么、为什么你的系统要这样装。

🏠 打个比方：毛坯房 vs 精装小盒子

🏚️ 传统部署 = 租毛坯大房子

房子是空的，你要自己装水电、拉网线、买家具、装空调，全都要自己动手。而且环境很容易乱——A 软件需要 Python 3.8，B 软件需要 Python 3.12，两个装在一起就打架，不是你死就是我活。

📦 Docker 容器 = 标准化"精装小盒子"

盒子里面已经打包好了：程序本身 + 它运行需要的全部依赖、配置、环境。拎起来就能住，不需要你再装任何东西。

🚀 这个盒子有多省心？

🌍 到哪都能跑

这个盒子可以在任何装了 Docker 的电脑 / 服务器上，一模一样地跑起来。绝不会出现"在我电脑能跑，到你那就跑不起来"的环境问题。

🧱 互不打架

每个盒子是独立的。A 软件要 Python 3.8、B 软件要 Python 3.12？各装各的盒子，互不干扰，各跑各的。

🔄 坏了换新

盒子出问题，直接换一个新的同款盒子。数据存在盒子外面，不会丢。

💼 交付省心

交付给客户时，直接给一个"装好所有东西的盒子"，双击启动就能用，不用远程折腾环境。

📊 现在 Docker 是主流吗？

✅ 结论：后端 / 服务器运维 / AI 服务部署，Docker 是绝对的主流标准工具

Docker 已经火了很多年，几乎所有互联网公司、云服务器、算力平台，部署项目时优先用 Docker。这是行业里最通用的做法。

不过也要说实话：普通日常家用、普通办公用户基本用不到它——它不是给个人电脑装软件用的工具，而是给"跑服务的电脑/服务器"用的。所以你不熟悉它，非常正常。

💡 小白解读：一句话记住
Docker 就是"把整个软件环境装进标准精装盒子的技术"。我们的获客系统装在盒子里，所以它到哪台电脑都能开箱即用、自己独立运行、升级不丢数据、互不打架——这就是为什么我们选择用容器来交付。
⚠️ 你需要做什么？
作为使用方，你完全不需要懂 Docker 怎么操作。交付的时候我们会把 Docker 装好、把盒子放好、把开关接好。你只需要：双击启动 → 打开网页 → 开始获客。就这么简单。
补充说明

Hermes 与 Docker：谁是司机，谁是车厢？

上一章说了 Docker 是"精装小盒子"，那 Hermes（赫尔墨斯，本系统的 AI 大脑） 和这个盒子是什么关系？很多客户第一次接触容易搞混，这里一次讲清楚。

🤖 Hermes = 司机（大脑）
  • 负责"想"：理解你的业务、生成话术、判断客户意向、决定怎么跟进
  • 负责"看"：看数据、看报告、看有没有新客户、看有没有人回复
  • 负责"动"：指挥采集器去抓线索、指挥发送器去发消息
  • 它是活的——每次对话、每条决策都是它在工作
📦 Docker = 车厢（房子）
  • 负责"装"：把 Hermes 需要的所有程序、配置、依赖打包好
  • 负责"跑"：给 Hermes 提供一个稳定、干净、不会互相污染的运行环境
  • 负责"运"：把整套系统搬到任何电脑上都能一模一样跑起来
  • 它是静的——它自己不思考，只负责当容器

用一个比喻理解：开餐厅

🍽️ Hermes 是厨师长，Docker 是后厨

想象一家中餐厅：

  • 厨师长（Hermes）决定今天做什么菜、按什么配方、怎么招待客人——这是智慧。
  • 后厨（Docker）保证灶台、锅具、调料、水电都齐全，厨师长说"炒"就能马上炒，而且不管换到哪个门店，后厨设备一模一样——这是环境。
  • 没有厨师长，后厨只是个空房间；没有后厨，厨师长连火都打不着。

所以：Hermes 负责"聪明"，Docker 负责"稳定"。两个缺一不可。

在你这套系统里，它们怎么配合？

环节Hermes 的角色Docker 的角色
采集客户决定搜什么词、判断谁像客户让采集工具稳定跑着，不卡不崩
AI 评分给每个客户打分、定等级提供评分引擎的运行环境
生成话术根据客户帖子内容写个性化消息保证话术引擎正常启动
发送消息决定发给谁、发什么、何时发让发送程序安全隔离地运行
看板展示汇总数据、生成报表把看板网页稳定地服务出来
⚠️ 重要：它们不是同一个东西，但一起工作
  • 你可能在别的电脑上见过"Hermes"或类似 AI 助手，但不是所有 Hermes 都自带获客系统——获客能力是专门为你的业务配置的。
  • Docker 是一个通用技术（行业标准），不只服务 Hermes，很多公司的软件都用它部署。
  • 对你来说，不用区分它们：你看到的是一个完整系统。只需要知道——AI 大脑负责思考，容器负责稳定承载，两者配合，系统才能 24 小时自动获客。
✅ 小白总结
Hermes 是司机，Docker 是车。司机负责想往哪开、怎么开；车负责把司机安全送到。没有车，司机只能走路；没有司机，车只是停在车库。你的系统里，它们俩已经配合好了——你只管上车（打开网页），剩下的交给他们。

3容器说明书——怎么开 / 关 / 升级 / 备份

这套系统打包成一个 Docker 容器，名字叫 altai-core。下面是每天会用到的基础操作（都是小白能照做的）。

🖥️ 怎么打开看板

  1. 打开浏览器（Chrome / Safari / Edge 都行）
  2. 地址栏输入：http://127.0.0.1:8890/
  3. 回车 → 看到"阿尔泰智能获客系统"仪表盘 = 一切正常
💡 小白解读
这个网页是容器自己带的"仪表盘"，不需要任何登录，也不需要 Hermes 开着。电脑一开机，容器就自己启动，网页随时能打开。

⚙️ 常用命令（给懂一点技术的人）

# 查看容器状态（Up + healthy = 正常）
docker ps --filter name=altai-core

# 启动 / 停止 / 重启
cd ~/altai-docker
docker compose up -d        # 启动（开机自启，一般不用手动）
docker compose stop         # 停止
docker compose restart      # 重启

# 看日志（出问题排查用）
docker logs -f altai-core --tail 100

# 升级到新版本
cd ~/altai-docker
git pull                    # 拉新代码
docker compose up -d --build  # 重新构建并启动

# 数据备份（自动 + 手动）
# 自动：每天 09:00 / 14:00 / 21:00 自动备份到百度网盘
# 手动：
tar -czf backup-$(date +%Y%m%d).tar.gz data/ config/

5设计理念——为什么这么设计

这套系统不是"把功能堆起来"，每个关键设计都有明确理由。给客户讲"我们为什么这么做"时用这一章。

🎯 五个核心设计原则

🛡️ 1. 安全第一：fail-closed

发送功能默认 disabled。配置错误 = 不发送（绝不乱发）。要真正发消息，必须逐项确认（send_mode 从 disabled → dry_run → approval → live）。

防"系统自己乱发骚扰客户"

🎯 2. 规则说了算

每条消息都有筛选条件 + 对话理由（R0-R4 规则链），可追溯、可审计、可防投诉。

不是 AI 乱聊，是规则驱动

🤖 3. 评分排序 + 配额分配

平台私信额度稀缺（VK 约 10 条/天）→ 不是看到谁发谁，而是 5 维评分排序，把每一天的额度花在最值的人身上。

筛得越准每一发越值钱

👤 4. 员工可追溯

每个员工登记名字 → 每次操作审计（谁/什么时间/IP/干了什么）→ 老板随时能查"谁在联系谁"。

不是监视，是保护业务资产

🧩 5. 容器化独立

不依赖 Hermes、不依赖任何第三方服务。一套代码 Mac/Win/云都能跑。升级只换镜像，数据卷保留。

6交付 SOP——从零到开箱即用

给客户的交付流程。核心原则：客户不需要懂 Docker、不需要懂技术，他要的是"打开就能用"。

📦 交付物 = 一个"交付包"

1️⃣ 镜像文件 / 构建脚本

altai-docker 镜像（可离线导入）或构建脚本（在线 docker build）。

2️⃣ compose + 配置

docker-compose.yml：端口/数据卷/环境变量/健康检查全配好。

3️⃣ 数据目录

config/（话术/关键词/黑白名单）+ data/（空业务库）。开箱即用。

4️⃣ 一键启动脚本

Mac 双击 启动.command，Windows 双击 启动.bat。

5️⃣ 交付文档

本说明书（网页版）+ 员工操作指南 + 交付与运维全攻略。

6️⃣ 自检工具

healthcheck + watchdog（8 项巡检）+ 自检页面。系统健康随时可见。

🚀 交付 7 步（小白可执行）

  1. 安装 Docker（远程帮忙装，或交付包内置引导）。Mac 装 Docker Desktop，Windows 装 Docker Desktop/WSL2。
  2. 解压交付包到任意目录（建议桌面，路径别带中文/空格）。
  3. 双击启动脚本。自动：检查 Docker → 导入/拉取镜像 → docker compose up -d → 自动打开浏览器。
  4. 看到运营看板 = 交付成功。绿色健康检查、引擎待启动、规则已就位。
  5. 员工登记：点右上角 👤 输入名字（员工追溯开始）。
  6. 平台登录：在浏览器登录 VK/WA/TG/IG/TikTok/速卖通（一次性，登录态保存）。
  7. 开始获客：点「▶ 开始获客」。扫描线动起来 = 系统在工作。
⚠️ 交付前必查
① 网络：海外平台需要科学上网（代理）——先确认客户网络环境。

为什么用容器而不是装个软件？

因为容器能解决传统软件最大的痛：环境问题。

传统部署软件就像租一套毛坯大房子：要自己装水电、家具、空调，环境很容易乱——A 软件要 Python 3.8，B 软件要 Python 3.12，两个就打架。而 Docker 容器相当于一个个标准化"精装小盒子"：盒子里面打包好了程序本身 + 运行需要的全部依赖、配置、环境，在任何装了 Docker 的电脑上都能一模一样地跑。

对比普通软件容器（我们做的）
安装每台电脑环境不同，容易装不上环境 100% 一致，一条命令启动
运行依赖桌面程序开着独立后台运行，开机自启
升级重新装，可能丢数据换新容器，数据卷保留
换电脑重新配一遍环境拷贝容器+数据，秒级迁移
💡 小白解读

电脑关机/睡眠⏸ 暂停（它跑在电脑上）上班开机就恢复，数据不丢

如果你们想全天候自动获客（比如晚上也能自动发消息），建议部署到云服务器（我们提供部署服务）。对于大多数公司，"上班时间开着电脑"就够了——员工反正也是白天聊客户。

升级会不会丢数据？

不会丢——三重保险：

① 数据独立存储

数据存在独立"数据卷"里，升级只换程序外壳（镜像），数据完全不动。

② 升级前自动备份

每次升级前先打版本快照（version.sh），出问题能一键回到升级前。

③ 每日云备份

每天 09:00/14:00/21:00 自动备份到你的百度网盘，电脑坏了都不怕。

升级流程很简单：交付方远程执行一条升级命令 → 新版本容器替换旧容器 → 数据自动接上 → 验证正常 → 完成。全程你不需要操作，也不影响当天使用。

💡 小白解读
升级像"换房子装修"：家具（数据）先搬出来放好，装完再搬回去。而且装修前还拍了照（版本快照），装砸了能一键恢复原样。

VK 是什么？为什么主做 VK？

VK = VKontakte，俄罗斯最大的社交平台，相当于"俄版微信 + Facebook"的结合体。月活用户 7000 万+，是俄罗斯人日常交流、做生意的主阵地。

为什么主做 VK？三个理由：

① 客户浓度最高

进口车商、电商卖家、批发商在 VK 上最活跃（很多只有 VK 没有其他平台）

② 信息最开放

VK 允许按关键词/圈子公开搜索帖子，能精准找到"正在找中国物流"的人

③ 沟通最直接

VK 私信是俄语区商务沟通主流方式，比 Instagram/TikTok 更适合 B2B 谈生意

平台角色为什么
VK主战场B2B 客户浓度最高，信息开放，私信直接
Telegram主战场俄语区商务沟通首选，群组线索丰富
Instagram辅助视觉种草，进口车商/电商卖家多
TikTok辅助年轻用户多，需住宅代理
WhatsApp私域成交主力，需先加通讯录
💡 小白解读
VK 就是"俄罗斯人的朋友圈+微信群"——你的目标客户（进口车商/卖家）每天泡在那。我们做的，就是去他们泡的地方精准找他们。
系统怎么判断"这个客户值得聊"？

AI 用 5 个维度给每个客户打分（0-100 分）：

维度看什么为什么重要
意向度是不是正在找物流/求购中国商品正在找的人最容易成交
匹配度是不是做中国进口的（车商/卖家/批发）不做中国生意聊了也白聊
账号质量活人/商家，还是僵尸号/广告号避免浪费时间在假账号上
画像完整度能不能拼出完整客户画像画像越全话术越准
触达价值客户体量、预算、成交潜力大客户优先聊

等级划分：80+ 分 S 级（重点），70-79 A 级（优先），60-69 B 级（观察），以下 C/D（暂不主动）。系统只让你聊 S/A 级，把有限的精力花在最可能成交的人身上。

💡 小白解读
就像销售经理给客户"贴标签"：A 类客户（正在找、有钱、能做）优先谈，C 类（随便问问）先放着。AI 帮你把 1000 个客户里最该聊的 20 个挑出来。
客户回复了怎么办？

客户一回复，系统立刻"交棒"给你——绝不擅自替你跟客户谈。

① 自动巡查

系统每 2 分钟检查一次有没有新回复（VK）

② 立即停手

检测到回复 → 立即停止对这个客户的自动发送

③ 转人工

标记 needs_human + 微信/看板通知你"有人回复了"

④ 你来接手

你打开聊天直接谈（系统给出客户画像+历史话术辅助你）

为什么不让 AI 继续聊？因为问价、谈条件的客户是最接近成交的，这种时候 AI 一旦说错话（报错价、说错时效），损失的是真金白银。所以设计原则是：自动获客，人工成交。

💡 小白解读
系统像个"前台"：帮你把客户约到店里，客户一进门（回复），前台立刻喊你（通知），你亲自接待（人工谈）。绝不让前台替你做主。
能同时多个员工用吗？

能，而且专门为"多员工协作"设计：

👥 员工登记

每个员工登记自己名字（2 秒），系统区分"谁在联系谁"

🕵️ 操作追溯

每次操作记录谁/什么时间/干了什么，老板随时查

📂 客资账号分离

可创建多个客资账号，各管各的客户池，不抢客户

📊 绩效透明

每个员工聊了多少、标记多少已联系，后台一目了然

适合什么规模：1 个老板 + 3-5 个业务员（典型外贸/物流团队）完全够用。每个员工打开网页 → 选自己名字 → 看自己的今日任务，互不干扰。

权限设计：普通员工只能看自己该看的（今日任务/线索工作台），管理员功能（平台开关/清空/设置）有密码保护，防止误操作。

💡 小白解读
就像办公室每个人有自己工位：各干各的活，老板能看每个工位的情况，但又不会互相抢客户、乱动别人的东西。

我们想扩展新平台怎么办？

随时可以扩展——架构是"插件化"设计的。

什么意思：系统不是把 6 个平台写死，而是每个平台是一个独立"插件"。要加新平台，就写一个采集器 + 一个适配器，插进去就能用，不影响现有平台。
